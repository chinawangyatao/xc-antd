# 智慧商业后台 UI 规范

版本：1.0；核对日期：2026-10-22。

适用范围：本仓库所有后续新增、生成、修改、重构的后台页面、业务组件及样式。AI 生成和人工开发采用同一标准。其他仓库复用时，需要同时接入其开发规则入口并重新核对组件版本，不能仅凭本仓库的配置声称全局生效。

## 1. 标准来源与优先级

视觉标准：[Mockplus《后台设计规范》](https://app.mockplus.cn/app/g8AKlXu7cA/design)。本文将已核对的常用要求转为实施和验收规则，组件页的详细变体仍以对应设计标注为准。

| 来源                                  | 用途与约束                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------ |
| 用户明确确认的 UI 规范变更            | 按指定范围更新本文件和实施基线；不能由一张新原型自动推导                       |
| Mockplus《后台设计规范》及组件标注    | 颜色、字体、布局、间距、尺寸、状态、交互外观的视觉依据                         |
| 本文件                                | 仓库内执行基线、组件映射、实施边界和验收规则；与设计稿不一致时记录并修正文档   |
| 当前安装的 `xc-antd` 源码、类型、示例 | 证明某项能力和 API 是否可用；默认外观不自动等于设计标准                        |
| 符合规范的既有页面                    | 复用业务组织、容器及宿主接入方式；旧页面偏差不能成为新标准                     |
| 业务原型、需求描述                    | 提取字段、规则、流程、信息层级和状态；原型中的颜色、尺寸、按钮和装饰不用于定稿 |

执行要求：

- 先将原型转换成业务清单，再选择规范中的页面和组件模式。不得把原型截图直接当作视觉还原目标。
- 不引入另一套审美或 UI 库，不自行增加设计规范和业务需求未定义的渐变、大阴影、圆角卡片、超大标题或宣传区。
- 不能辨认的标注、未覆盖的特殊组件应查看对应规范页。暂时无法确认的值必须标注为待核实，不得编造为设计定值。
- 本次固化的是下列已读取的常用规范，不声称已经逐个转录全部组件的所有变体。后续使用未细化的变体时，补查相关设计页即可，无需重读整个项目。

## 2. 颜色、尺寸与样式入口

### 2.1 唯一实施入口

- 应用级主题入口：[`src/styles/theme/themeToken.ts`](../src/styles/theme/themeToken.ts)，由 [`AppShell`](../src/components/AppShell.tsx) 的 `ConfigProvider` 注入。
- 私包样式入口：`import 'xc-antd/style'`，当前由 [`src/main.tsx`](../src/main.tsx) 引入。业务页面不重复导入私包内部文件。
- 业务样式优先读取 `theme.useToken()`，或使用由统一主题派生的项目语义变量；不在页面重复定义品牌色、错误色、字号和组件圆角。
- 主题 Token 是实施机制，下面的设计值是目标。当前主题仅显式配置品牌色和圆角，不能假定其他目标已经实现；缺项见[整改清单](xc-antd整改清单.md)。
- 不从旧的 [`variables.scss`](../src/styles/variables.scss) 继承与本规范冲突的颜色、圆角或阴影。后续统一应修改源头，不能继续增加平行主题。

### 2.2 功能色

来源：`Color_Light Mode`、`Color Tokens`。颜色按语义使用；成功、警告和错误状态同时提供文字或图标含义。

| 语义        | 常态（6） | Hover（5） | 按下（7） | 禁用色阶（3） | 浅交互色（2） | 浅底色（1） |
| ----------- | --------- | ---------- | --------- | ------------- | ------------- | ----------- |
| 品牌 / 链接 | `#165DFF` | `#4080FF`  | `#0E42D2` | `#94BFFF`     | `#BEDAFF`     | `#E8F3FF`   |
| 错误 / 危险 | `#F53F3F` | `#F76560`  | `#CB2634` | `#FBACA3`     | `#FDCDC5`     | `#FFECE8`   |
| 警告        | `#FF7D00` | `#FF9A2E`  | `#D25F00` | `#FFCF8B`     | `#FFE4BA`     | `#FFF7E8`   |
| 成功        | `#00B42A` | `#23C343`  | `#009A29` | `#7BE188`     | `#AFF0B5`     | `#E8FFEA`   |

设计稿中还列出第 4 色阶；仅在对应组件标注引用时使用，不自行扩展状态语义。`Color Tokens` 同时出现 `active` 与 `Active` 命名，分别关联深色按下态和第 2 色阶；代码中应使用明确语义名称，不能直接复制大小写易混淆的变量名。

### 2.3 文字与中性色

| 设计语义              | 颜色 / 设计引用                        | 对应实施方向                     |
| --------------------- | -------------------------------------- | -------------------------------- |
| 主文字、主图标        | `#1D2129`                              | `colorText`                      |
| 次文字                | `#4E5969`                              | `colorTextSecondary`             |
| 占位和辅助文字        | `#86909C`                              | `colorTextPlaceholder`、辅助说明 |
| 禁用文字              | `#C9CDD4`                              | `colorTextDisabled`              |
| 反色文字              | `#FFFFFF`                              | 反色文字 Token                   |
| 品牌文字、链接        | Brand6：`#165DFF`                      | 品牌和链接 Token                 |
| 页面底层背景          | `@bg-color-page` → Gray2               | 页面背景语义 Token               |
| 主容器背景            | `@bg-color-container` → White          | `colorBgContainer`               |
| 次容器背景            | `@bg-color-secondarycontainer` → Gray1 | 次容器语义 Token                 |
| 组件背景 / 默认分割线 | Gray3                                  | 填充 / 分割线语义 Token          |

设计稿展示普通灰和冷灰两套色板。`Color Tokens` 中的普通 Gray1 / Gray2 / Gray3 / Gray4 / Gray6 对应 `#F3F3F3` / `#EEEEEE` / `#E7E7E7` / `#DCDCDC` / `#A6A6A6`；不能因旧页面使用冷灰而混淆同名色阶。特定组件有单独标注时按该组件执行。

中性交互色也按语义映射：主容器 Hover → Gray1，按下 → Gray3；次容器 Hover → Gray2，按下 → Gray4；组件 Hover → Gray4，按下 → Gray6，禁用背景 → Gray2。统一到主题后由组件读取，不逐页硬编码。

### 2.4 间距、字体、圆角与阴影

- `Layout` 的间距阶梯：**4、8、12、16、24、32、40、48、64、96、160px**。普通业务布局从阶梯选择；按钮内边距、滚动条等有明确组件标注时使用对应特例。
- 表单、表格、抽屉等相同场景的留白必须一致，不能为了接近原型随意增加 18、20、22px 等页面级间距。历史值不作为新增依据。
- 字体沿用项目统一字体栈和组件文本 Token，不为单个页面更换字体；字号、行高和字重按组件标注。当前私包 `FormGroup` 标题为 16px / 24px、字重 600，此处是源码基线记录，不推导为所有页面标题的统一设计值。
- 普通按钮三档高度：小 24px、中 32px、大 40px；默认使用中档，同一操作区保持一致。按钮尺寸区标注圆角为 3px，与当前应用 `borderRadius: 3` 一致。
- 按钮概览中另有一处 6px 圆角示意，与尺寸区及图标按钮的 3px 不同。本仓库先按尺寸区和当前主题的 3px 执行，不把该示意推广为全局圆角；需要变更时先明确适用变体。
- 阴影使用 `Shadow` 定义的三级语义：基础投影用于组件 Hover / 拖动；中层投影用于下拉、选择器、气泡确认；上层投影用于全局提示和消息通知。普通页面内容区不主动加悬浮阴影。

| 设计阴影       | 标注参数                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------- |
| `@td-shadow-1` | `0 1px 10px rgba(0,0,0,.05), 0 4px 5px rgba(0,0,0,.08), 0 2px 4px -1px rgba(0,0,0,.12)`            |
| `@td-shadow-2` | `0 3px 14px 2px rgba(0,0,0,.05), 0 8px 10px 1px rgba(0,0,0,.06), 0 5px 5px -3px rgba(0,0,0,.10)`   |
| `@td-shadow-3` | `0 6px 30px 5px rgba(0,0,0,.05), 0 16px 24px 2px rgba(0,0,0,.04), 0 8px 10px -5px rgba(0,0,0,.08)` |

这些是设计参数，不表示私包已经导出了 `td` 变量。应在主题适配层映射，不能在各页面复制一套。

## 3. 页面容器与响应式

- 标准数据页按“宿主导航与页签 → 页面内容 → 筛选 / 工具栏 → 表格或业务内容 → 分页”组织；按业务需要省略区块，不重复生成宿主导航。
- 复用 [`Layout`](../src/components/Layout.tsx) 和 [`Container`](../src/components/container/index.tsx)。当前 Container 默认扣除宿主导航 55px 与页签 48px，这是项目集成值，不是通用组件必须写死的常量。
- 表格所在内容区域随父容器伸缩，左右安全区各 **24px**。由对应容器负责一次留白，避免 Container、页面和表格组件层层叠加产生多重内边距。
- `表格规范` 标注父级最小宽度为 **848px**。这是桌面数据区设计边界，不能把它直接设为所有页面或移动端 `body` 的最小宽度。更窄的可用区域应在数据区滚动、收起辅助栏或改列布局，保留操作可达性。
- flex 子区需要正确的 `min-width: 0`、`min-height: 0` 和剩余高度分配。长表格在表体滚动；长表单在内容区滚动；固定头部、底部操作和分页不能被挤出可见区。
- 以微应用容器的实际可用宽度决定布局，不能只看浏览器窗口，也不能整体缩小页面来适应尺寸。
- 顶部导航属于宿主。其规范示例为 1920、1440、960、768px；收缩时先收起收藏应用，再收起固定应用，规范注明小于 768px 后不继续缩小。只有开发宿主导航时才处理该规则，业务页面不复制一套导航。
- 本项目的小屏业务内容保留必要的换行、滚动和全宽浮层适配；不得声称设计稿已经提供完整移动端视觉方案。

## 4. 组件选型与真实 API 边界

本次核对：`xc-antd@2.2.35`、`antd@6.6.3`。升级后重新读取安装版本；以下映射不是版本无关的 API 保证。

| 业务需要                       | 优先实现                                                                    | 边界                                                                            |
| ------------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 单字段编辑 / 只读              | `TextField` 及其真实 `valueType`                                            | 原子字段，不负责整个表单状态；编辑需明确 `mode="edit"`                          |
| 按字段配置组织表单             | `SchemaForm`                                                                | 使用 `schema`、`formProps`、`formItemProps`、`fieldProps`；不臆造其他表单 API   |
| 手工业务表单分组               | `FormGroup` + 项目已有 `Form` / `Col`                                       | `FormGroup` 提供 section 和 Row，调用方负责字段与 Col                           |
| 查询、请求、分页、选择、列设置 | `CrudTable`                                                                 | 后端查询和权限规则由业务层负责                                                  |
| 本地数据过滤、行内新增编辑     | `HocTable`                                                                  | 不替代远端 `CrudTable` 的请求契约                                               |
| 搜索列表 / 主副标题列表        | `ListPanel`                                                                 | 复用筛选、添加、选中、右键菜单能力                                              |
| 层级搜索、图标、右键、拖拽树   | `ListTree`                                                                  | 可用 `toolbarExtra`、`contextMenu`、`dragDrop` 等真实接口；业务层维护层级合法性 |
| 分组标签多选                   | `GroupedSelect`                                                             | 不重新手写同类选择面板                                                          |
| 图片上传 / 裁剪                | `ImageUpload`、`ImageCropDrawer`                                            | 普通文件资源库并不等于图片上传能力                                              |
| 业务抽屉 / 表单弹窗            | `ActionDrawer`、`ActionModal`                                               | `onConfirm`、`onCancel`、`onOpenChange`；抽屉用 `size`，弹窗用 `width`          |
| 富文本、地图、二维码、媒体     | `RichTextEditor`、`AmapEditor`、`QRCode`、`VideoPlayer` / `MusicPlayer`     | 使用已导出的组件与类型；不能另造基础替代品                                      |
| 脱敏、按钮权限                 | `SensitiveData`、`PermissionProvider` / `PermissionGuard` / `usePermission` | 权限与真实业务逻辑保持一致                                                      |

当前 `xc-antd` **不导出名为 `Button`、`Form`、`Tabs`、`Tooltip`、`ConfigProvider` 等的 Ant Design 同名基础组件**。不能生成 `import { Button } from 'xc-antd'` 这样的不存在的导入。

当前项目已有的补充来源是 `antd`：主题与上下文（`ConfigProvider`、`App`、`theme`）、布局（`Row`、`Col`、`Space`、`Splitter`）、按钮与表单上下文、导航（Tabs / Menu / Steps / Pagination）、反馈（Tooltip / Alert / Empty / Spin / message / notification / Popconfirm）以及缺少私包等价能力的基础展示组件。图标沿用 `@ant-design/icons`。

这是对已知能力缺口及既有来源的明确说明，不允许用它替换私包已有的 `TextField`、表格、表单、列表、上传和业务浮层。新增未列出的替代方案仍须先说明缺失能力和影响；私包后续补齐后优先迁回统一入口。

## 5. 按钮、链接与状态

- 页面主要操作使用品牌填充按钮；次操作使用规范中的中性 / 描边按钮；低强调度或行内操作使用文字 / 链接按钮。不得将所有按钮都做成主按钮。
- 查询表单的顺序遵循表格设计示例：**展开 / 收起 → 查询 → 重置**，位于最后一组右侧；不能把一张原型的不同顺序复制为新标准。
- 普通按钮中档横向内边距为 16px；小档为 8px，大档为 24px；图标与文案间距 8px，常规配套图标 16px。通过组件主题和公开能力实现，不逐按钮覆盖内部 DOM。
- 仅图标按钮必须有 Tooltip 和可访问名称；不要使用无法聚焦的 `div` 模拟按钮。
- 使用组件提供的 Normal、Hover、Active、Disabled、Loading 状态。禁用状态不能触发操作，加载状态应阻止重复提交；失败后恢复可操作状态。
- 删除、作废等不可恢复或高影响操作先明确对象、后果并二次确认，确认按钮采用相应语义；不要套用设计示例里的“确认删除”作为所有表单文案。
- 链接、按钮、危险操作和只读文本的用途保持一致；不可仅凭蓝色表达“可点击”。

## 6. 表单与表单组

- 业务表单优先 `SchemaForm`，复杂业务流程可使用 `FormGroup` 组合；标签、必填标识、校验提示由真实表单机制承担，不能用红色星号和静态文本伪造。
- `form-group表单组` 标注：容器上下及左右留白 24px，标题到内容 16px，字段标签到值 / 控件 4px，相邻字段行间距 16px。同组字段按可用宽度保持一致的列对齐。
- 表单可以横向标签、顶部标签或行内查询，按对应业务模式选择；同一表单不随意混用标签对齐方式。不得为了原型外观破坏项目现有模式。
- 输入、数值、日期、时间、单选、多选等优先用 `TextField` 已支持的类型。选项标识、文案、禁用条件来自业务数据，不用原型示例值代替真实选项。
- 正常、只读、禁用、加载、空值、错误、警告等状态使用真实组件能力；只读详情不能表现为仍可编辑的禁用输入框堆叠。
- 校验错误靠近对应字段，说明具体原因；确认失败时保留输入与当前浮层，用户应能继续修正。校验未通过不得关闭浮层或提示成功。
- 标签与输入建立实际 `id` / `htmlFor` 关联，必填和错误信息对读屏可识别。不能仅保证视觉上出现标签。
- 多行文本、联动字段、动态增减字段应保留对应业务校验和边界；说明文字不代替标签，占位文字不承担唯一的字段说明。
- `/param` 继续遵守根 `AGENTS.md` 的专属 JSON 渲染契约，配置内容与编排仍写入其 JSON；本规范不把 JSON 体系扩展到其他页面。

## 7. 表格与分页

- 普通管理列表优先 `CrudTable`；在现有能力范围内配置筛选、工具栏、选择、分页和列设置，不用原生表格复制一套。
- 筛选区保持标签、控件、操作组对齐；随内容区宽度重排，不能溢出或用 `display: none` 丢失业务上必须可达的筛选项。折叠行为使用组件状态。
- 表格宽度自适应，业务列按内容分配剩余空间；必要时表体横向滚动。基础选择 / 序号和右侧操作列在需要时固定，避免关键操作随长表消失。
- `表格规范` 的列参考：选择列 48px、序号列 60px；常规操作列示例最小 112px、最大 224px，长操作名称另示例自适应。配置时计入单元格留白，不把“内容宽度”直接当作完整列宽。
- 单元格左右留白按标注为 16px。内容宽度示例包括：姓名 / 星期 / 占比 64px，日期 / 金额 / 工号 / 手机号 / 城市 / 景区名称 88px，账号 ID / 部门 128px，日期时间 148px，邮箱 / 地址 160px；按实际列语义选择，不一律平均分配或全部写死。
- 文本按语义对齐，金额 / 数量便于纵向比较；长名称截断后能够查看全文。不能以增加行高或页面横向溢出来解决所有长文本。
- 表格、空状态、加载状态和分页占用稳定布局；只有表体滚动，固定表头与操作列保持对齐，不应出现双重横向滚动条。
- 行内操作保持统一顺序与间距，容纳不下时使用组件菜单承接更多操作，不无限堆叠按钮。
- 分页规范采用总数、每页数量、前后页及当前页 / 总页数的组合，按 `Pagination分页示例` 选择变体；保留查询条件和页大小语义。私包尚无项目预设时列出差异，不将默认完整页码条直接认定为规范已满足。
- 不为了“看起来一样”关闭必要排序、校验、选择或权限逻辑；也不凭视觉规范新增需求未要求的工具按钮。

## 8. 列表、树与选项卡

- 导航列表按 `列表规范` 选择纯标题、标题 + 副标题、带筛选或带“所有主题”分隔的变体，复用 `ListPanel`。
- 层级导航复用 `ListTree`；搜索、筛选、添加、刷新、选项卡与右键菜单使用现有公开扩展点组合。上移 / 下移等业务菜单由调用方传入，不认为默认三个菜单就是完整业务需求。
- 选中态、Hover 态、禁用态分别清晰表达，不能仅更改字体颜色而丢失背景与焦点提示。
- 长标题应能查看完整含义。树的横向滚动与省略提示按场景二选一，不同时裁掉内容又不给访问方式。
- Tabs 按规范采用线型、可关闭、卡片或图标变体；同层内容采用一致样式，空间不足时可滚动，不压缩为无法阅读的标签。
- Steps 只表达有顺序的业务流程，使用已完成、进行中、未开始、错误等真实状态，不以装饰性步骤条替代普通 Tabs。

## 9. 弹窗、抽屉与反馈

- 对话框用于局部确认、提示或有限表单，抽屉用于保留列表上下文的编辑 / 详情；先选场景再组织内容。
- **弹窗**：底部按钮靠右，次操作在左、主操作在右，即“取消 → 确认 / 保存”；普通弹窗设计宽度范围 480–960px，全屏变体另按设计页处理。
- **抽屉**：底部按钮靠内容区左侧，主操作在前、取消在后，即“保存 / 确认 → 取消”；头部标题和关闭按钮、内容区、固定底栏分层清晰。
- 项目抽屉宽度从 [`DRAWER_SIZE`](../src/constants/drawer.ts) 的 480 / 720 / 960 / 1440px 四档选取。这是项目已有尺寸约定，不声称 Mockplus 给出了相同四档；小屏应限制在实际可用宽度内。
- 设计稿有拖拽调整宽度的抽屉变体。当前 `ActionDrawer` 继承的 Ant Design 类型已支持 `resizable`，按实际需要使用，不得把它误报为必须新增的能力。
- 项目默认禁止点击遮罩关闭。`ActionDrawer` / `ActionModal` 当前会自行设置遮罩默认值，调用方需显式传入 `mask={{ closable: false }}`，不能假定 AppShell 的默认值必然生效。
- 统一挂载到项目浮层容器 `#mask-layer`，保持主题、层级和微应用边界；多层浮层不能互相遮挡、丢失焦点或滚动穿透。
- 有未保存修改时按既有统一确认机制处理；取消确认后回到原表单，不能清空已填内容。关闭后焦点应回到触发入口。
- 全局短反馈使用项目统一 message，重要持久通知使用 notification，区块内提示使用适当 Alert，临近操作确认使用 Popconfirm。按对应规范变体选择，不额外生成巨大的错误面板替代短提示。
- 反馈显示真实请求结果；加载、成功、失败不能用延时和假成功模拟。组件确认回调保留浮层时，还需由业务提供可见的错误原因。

## 10. 上传与滚动

- 图片上传、预览、批量裁剪使用 `ImageUpload` / `ImageCropDrawer`；上传状态、数量、格式、大小限制与失败反馈必须与业务规则一致。
- `特殊组件` 还展示图片、文件、音频、视频共用的资源选择面板，含分类 Tabs、搜索、总数、已选数量和网格选择。这不是当前 `ImageUpload` 的完整能力，需要该场景时按整改清单补能力，不假定私包已有通用资源库。
- `Scrollbar` 标注：大号槽位 10px，默认滑块 6px、悬停 / 点击 10px；小号槽位 6px，默认滑块 4px、悬停 / 点击 6px，水平与垂直规则一致。
- 滚动样式应由统一样式或私包能力承担；原生平台差异需在验收中说明，不逐页创建不同滚动条。不能为了隐藏滚动条让长内容无法访问。

## 11. 实施与交付自检

### 11.1 开始前

1. 读取本规范和当前任务涉及的[整改项](xc-antd整改清单.md)，确认原型只提供业务逻辑。
2. 查对应规范页及当前安装的私包导出、类型、源码 / 示例和项目调用方式，列出本次用到的组件与公开配置。
3. 先尝试主题、公开 Props 和现有组件组合。只有真实缺口才提出私包修改或替代说明；整改文档中的建议名称不能直接作为已存在的 API 调用。

### 11.2 交付自检

每个涉及 UI 的任务都要对下面项目给出“通过 / 不适用 / 存在差异 / 待视觉验收”的实际结论。只检查改动范围和直接影响，不要求额外创建一份报告文件。

### 11.3 验证与结论

- 文档改动只做内容、链接和差异核对。代码改动执行最小相关静态检查、类型检查及必要隔离测试；不得触发构建、真实接口或生产写入。
- **Codex 禁止执行任何等价构建命令**，包括 `vite build` 及各种包管理器的 build 脚本。构建和最终运行验收由用户执行，根 `AGENTS.md` 的构建约束保持有效。
- 用户明确要求浏览器验证时，才渲染对应页面、状态和必要宽度；使用隔离数据，不以访问真实业务服务换取截图。桌面重点检查 1440 / 1920px、较窄容器及长内容；需要移动适配时补查实际小屏。
- 未实际渲染时只能报告“静态核对通过，视觉待用户验收”。静态检查不能证明所有像素、浮层定位和响应式表现正确。
- 已知差异影响本次 UI 时，先修正范围内可解决的问题；无法通过公开能力满足的差异列出对应整改编号和阻塞范围，不能标记为完全符合规范。
- 这里的“确认”指实现者自检和有证据的验收结论，不要求每次修改都停下来请求用户审批。

建议交付说明用一句或两句写清：本次适用规范 / 组件、检查结果、视觉验收状态、尚存差异或“无新增私包修改项”。
