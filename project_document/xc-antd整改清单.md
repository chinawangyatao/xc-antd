# xc-antd 对齐 UI 规范整改清单

核对日期：2026-10-22。安装基线：`xc-antd@2.2.35`、`antd@6.6.3`。对照标准：[UI规范](UI规范.md)及其 Mockplus 来源。

第 1～5 节保留初始核对时的差异与建议，当时未修改组件包、业务页面、主题或依赖。2026-10-23 在组件库工作区完成的源码整改及验证见第 6 节；应用应按实际发布版本接入，不能将尚未发布的源码能力直接当作已安装能力。

P0：先处理会普遍影响新页面一致性的差异；P1：再收敛重复适配与表单正确性；P2：仅在业务需要时扩展能力。优先级表示维护顺序，实际任务只受其涉及的缺口影响。

## 1. 私包需要处理的明确差异

### XC-01 / P0：统一主题 Token，移除组件内固定品牌色与状态色

- **目标**：品牌色 `#165DFF` 及 Hover / 按下 / 禁用等色阶、文本、中性背景、边框、分割线和阴影由同一主题驱动。
- **证据**：`FormGroup/style.css` 标题条固定 `#0052D9`；`ListPanel/style.css` 选中 / 焦点固定 `#1677FF`、背景固定 `#E6F4FF`；`ListTree/style.css` 的拖拽变量同样固定为这组颜色。`CrudTable/style.css`、`HocTable/style.css` 还包含固定蓝、灰、错误色和间距。
- **建议修改**：在私包维护统一语义 Token / CSS 变量映射，兼容应用 `ConfigProvider` 的主题；提供符合本规范的可选择预设，避免各业务仓库重复覆盖。所有自定义部分均应读取预设或主题，不能只让内部 Ant Design 控件跟随主题。
- **验收**：使用项目预设时对齐规范；更换品牌主题时，分组标题、列表选中、树拖拽、表格选择提示、字段错误和浮层同步变化，正常 / Hover / 按下 / 禁用态无旧色残留。

### XC-02 / P0：弹窗与抽屉分别定义底栏，修正未保存提示尺寸

- **目标**：弹窗右对齐、“取消 → 确认”；抽屉左对齐、“确认 → 取消”；普通对话框宽度落在 480–960px。
- **证据**：`ActionModal` 和 `ActionDrawer` 共用 `ActionOverlayFooter`；`shared.tsx` 固定先输出主按钮再取消，主按钮 `minWidth: 88`；`style.css` 固定左对齐且按钮相隔 16px。内置 `UnsavedChangesPrompt` 固定宽度 420px。
- **建议修改**：在共享底栏内部区分 Modal / Drawer 布局及按钮顺序，尺寸和间距读取对应组件 Token；内置未保存提示采用规范内的尺寸。若旧消费者依赖当前行为，通过项目预设或明确兼容选项迁移，不能无说明改变所有消费者。
- **现有可用方式**：两个组件均有公开 `footer` 插槽，可在有明确项目组合方案时使用；无需复制浮层源码。项目 [`useActionConfirm`](../src/hooks/useActionConfirm.tsx) 已使用右对齐确认布局，可继续复用符合规范的部分。
- **验收**：普通弹窗、抽屉、未保存确认分别核对顺序、对齐、文案、Loading、键盘焦点及窄屏布局；短文案不被不必要的 88px 最小宽度拉宽，长文案不截断。

### XC-03 / P0：CrudTable 查询区顺序、留白和响应式需要项目预设

- **目标**：按规范配置“展开 / 收起 → 查询 → 重置”，筛选随内容容器宽度重排，边距与页面安全区统一。
- **证据**：`CrudTable/SearchForm.tsx` 固定“展开 / 收起 → 重置 → 查询”；`Row gutter={20}`，列固定 `xs=24 / sm=12 / lg=6`；`defaultColsNumber` 被限制最大 3。`CrudTable/style.css` 的搜索、工具栏及表体内部多处写死 20px。当前项目有调用方传入 `defaultColsNumber: 4`，但仍会被私包限制为 3。
- **建议修改**：补充规范预设或公开布局配置，使按钮顺序、列数 / 断点、折叠数、内外留白可一致设置；布局应适应微应用或 Splitter 后的实际内容宽度。不要让页面通过深层选择器重排按钮。
- **验收**：在较宽和 848px 数据区、左侧树宽度调整、筛选展开 / 收起、按钮 Loading 等场景检查控件宽度与对齐；调用方传入受支持的列数后确实生效。

### XC-04 / P1：FormGroup / SchemaForm 需要统一表单组间距

- **目标**：实现表单组的 24px 容器留白、16px 标题到内容及行间距、4px 标签到控件，并让只读和编辑排列一致。
- **证据**：`FormGroup/style.css` 没有容器内边距，标题下留白为 12px，body 顶部为 16px；组件默认 `gutter=16`。`SchemaForm` 使用 Ant Design 默认字段间距，不能直接视为所有表单组均已符合设计。项目目前在业务样式中另补分组 padding。
- **建议修改**：增加可复用的规范布局预设，或提供足够的公开布局 Token；明确由哪一层负责 padding 与字段间距。保留当前基础布局用法，不强迫纯业务栅格重复增加外留白。
- **验收**：一列 / 多列、无标题 / 有标题、只读 / 编辑、长标签 / 校验错误的布局一致；不会同时从业务和私包获得两份 padding。

### XC-05 / P1：SchemaForm 控件透传需保证标签关联与失焦校验

- **目标**：表单标签能够聚焦真实输入，`validateTrigger="onBlur"` 等配置确实作用到输入，状态信息可访问。
- **证据**：`SchemaForm/SchemaForm.tsx` 中间层 `SchemaFieldControl` 只接收并向下管理 `value` / `onChange` 等属性，没有接收 Form.Item 注入的 `id` / `onBlur`。项目 [`printTemplates.ts`](../src/pages/Param/schema/printTemplates.ts) 当前需要在 `fieldProps` 中显式填入 id、ARIA 属性和 onBlur 才补齐行为。
- **建议修改**：贯通 Form.Item、SchemaFieldControl、TextField 到实际控件的标准属性与 ref，制定与显式 `fieldProps` 的合并优先级，避免一边修复透传一边重复触发事件。
- **验收**：点击标签能聚焦输入；仅配置 `onBlur` 校验时真实失焦触发；错误说明 / 必填可被识别；文本、数字、选择、单选、复选与日期类型均验证适用行为。

### XC-06 / P1：表格规范能力应在 CrudTable / HocTable 内复用

- **目标**：单元格 16px 左右留白、规范列宽策略、溢出全文、固定列 / 表头对齐、表体滚动和分页位置稳定，并提供规范中的分页组合。
- **证据**：两个表格主要使用底层 Ant Design 的默认表现，私包 CSS 又加入内部 20px padding。`CrudTable` 已有 `adaptiveHeight` 和 `tableProps`，项目仍在 [`ScenicResourceManagement/styles.module.scss`](../src/pages/ScenicResourceManagement/styles.module.scss) 中深度适配表格边框、行高、滚动层级和表头 / 表体对齐，并复用业务内的 `OverflowTooltipTableCell`。
- **建议修改**：将可通用的规范表格预设、长文本策略、分页预设及稳定滚动布局纳入私包；复用现有 `columns` / `tableProps` / `adaptiveHeight`，不要新增一套替代表格。列的业务含义和最终宽度继续由调用方配置。
- **验收**：短数据 / 长数据 / 空表 / 加载 / 固定列 / 横向滚动时无错位，分页始终可达；不需要页面重复多组 `.ant-*` 和 `!important` 覆盖。

### XC-07 / P1：滚动条统一到规范尺寸与状态

- **目标**：大号槽位 10px，滑块 6→10px；小号槽位 6px，滑块 4→6px，默认与 Hover / 按下有明确变化。
- **证据**：`ListTree/style.css` 横向滚动规则写死 WebKit 滚动槽 8px、thumb 的 2px 边框和固定 `#B7C0CC`，当前无统一的项目大 / 小号滚动预设。
- **建议修改**：提供统一样式能力或可复用滚动容器，约束各私包组件使用同一套规则；对于浏览器 / 系统限制保留原生可用性，明确实际支持范围。
- **验收**：水平、垂直以及大 / 小号可选；Hover 不引发布局跳动；内容与键盘滚动仍可用；树和表格不会各自出现不同的滚动槽占位。

## 3. 已有能力，不应重复列为缺失

- **拖拽抽屉宽度**：`ActionDrawerProps` 继承 `DrawerProps`，当前 `antd/es/drawer/Drawer.d.ts` 已声明 `resizable?: boolean | DrawerResizableConfig`。先使用并验证该公开能力。
- **普通业务浮层**：已有 `ActionDrawer` / `ActionModal` 及自定义 footer、异步确认和未保存提示；问题在规范默认值与边界，不需要另造基础浮层。
- **树 / 列表搜索、筛选、按钮、右键和拖拽**：已有 `ListPanel` / `ListTree` 的公开配置，Tabs 和额外操作可以组合；菜单上移 / 下移属于调用方业务动作。
- **图片批量裁剪**：已有 `ImageCropDrawer` / `ImageUpload`；混合资源库和比例锁定才是不同的能力边界。
- **权限与脱敏**：已有真实组件和上下文，不因本次规范工作新增另一套权限或脱敏系统。

这些是源码层面对差异的核对，**尚未对所有历史页面做浏览器视觉审计**，不能视为旧系统问题的完整清单。

## 5. 实施顺序与关闭条件

1. 先统一设计预设和 Token（XC-01、APP-01 / 02），再处理浮层与查询区（XC-02 / 03），避免各组件重复定值。
2. 收敛表单透传、间距、表格和滚动行为（XC-04～07），有目标隔离测试和实际组件验收证据后发布私包版本。
3. 应用显式升级到可核对版本，保留必要兼容；确认目标场景通过后，再移除对应页面适配。现有 `patches/xc-antd@2.2.35.patch` 处理的是 GroupedSelect 删除气泡随滚动关闭，不能把它误认为本规范的主题或布局补丁。
4. 按实际需要实施 P2。缺少一个未使用的组件不阻塞所有页面，新增业务也不能假定建议 API 已经发布。

每项关闭需记录：采用的私包版本 / 变更、影响的应用配置、规范对应场景和验证结果。静态检查通过与视觉通过分开记录；本仓库 Codex 仍不得执行构建，最终运行验收由用户完成。仅凭修改了文档、增加了 Props 声明或“与旧页面一样”，均不足以关闭整改项。

## 6. 2026-10-23 组件库源码实施记录

实施位置为 `xc-antd` 组件库工作区，包版本仍为 `2.2.35`，本次改动尚未发布。初始审计中的应用路径属于来源项目；本节以当前组件库源码与示例为准。本机工作区子包解析到 `antd@6.5.0`，根目录安装为 `6.4.3`，不以来源项目的 `6.6.3` 代替本机事实。

优先使用原生配置：导出 `xcTheme`（`ThemeConfig`）、`xcConfigProviderProps`（可 JSON 序列化的 `ConfigProviderProps`）和 `xcTablePagination`（原生分页配置）。接入与兼容说明见 [组件包 README](../packages/xc-antd/README.md#ui-规范配置)，文档站入口已接入预设。应用无需替换为另一套 Provider；浮层挂载点继续由宿主配置。

| --- | --- | --- |
| XC-01 | 原生主题预设包含功能色、文字、中性色、尺寸、圆角、阴影及 Button / Form / Table / Drawer Token；分组、列表、树拖拽、表格与列设置浮层读取最近 ConfigProvider 的 Token | 已验证自定义品牌 / 背景的主题传递；完整状态与视觉待验收。切换品牌时遵循原生 Token 合并规则，显式设置过的派生色阶需要同步覆盖 |
